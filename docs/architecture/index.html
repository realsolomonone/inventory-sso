1. What this is

Terragrunt creates the same read-only IAM role in every IAM Identity Center account. Python then proves the role exists and matches policy. Operators never run terraform against this repo. Leadership opens one HTML file.

2. What the role can and cannot do

AllowedNot allowed
Read Resource GroupsCreate, change, or delete resources
Read tags (tag:Get*)Write tags or IAM
Assume only from Identity Center rolesLong-lived access keys on the role

Trust: sts:AssumeRole + TagSession, condition ArnLike aws-reserved/sso.amazonaws.com/*.

SidActionsResource
ViewSpecificResourceGroupresource-groups Get/List/Searcharn:PARTITION:resource-groups:*:ACCOUNT:*/*
TaggingReadOnlytag:GetResources, GetTagKeys, GetTagValues*

3. Deploy (run these)

Always terragrunt run --all from infra/live/accounts. Do not use run-all. Do not run from infra/live.

cd ~/workspace/inventory-sso
./scripts/doctor.sh
./scripts/sso-login.sh --all
./scripts/sso-profiles.sh --check
./scripts/stacks-generate.sh
cd infra/live/accounts
terragrunt run --all plan
terragrunt run --all apply

One account: cd infra/live/accounts/PROFILE && terragrunt apply
Destroy: cd infra/live/accounts && terragrunt run --all destroy — never from verify-accounts.

4. Verify (one command)

./scripts/verify.sh
FileUse
reports/executive.htmlPass / fail / missing by account
reports/role-verify.htmlPer-check detail if a row failed

  • MISSING apply has not run in that account
  • DENIED SSO expired — login, don’t redeploy
