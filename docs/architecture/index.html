What we built

Terragrunt deploys the same read-only IAM role across every IAM Identity Center account. Python then proves the role exists and matches policy. Leadership opens one HTML file.

What the role can and cannot do

AllowedNot allowed
Read Resource GroupsCreate, change, or delete resources
Read tags (tag:Get*)Write tags or IAM
Assume only from Identity Center rolesLong-lived access keys on the role

How you know it worked

Ask operations for reports/executive.html.

  • PASS role present and policy matches in that account
  • MISSING deploy has not been applied there
  • DENIED SSO session expired — login, don’t redeploy

Ask in the room

  • How many accounts passed vs need attention?
  • Is trust limited to Identity Center?
  • Where is the signed report? reports/executive.html

Control plane vs module

Terragrunt is the operator path. Terraform exists only in infra/modules/. root.hcl generates the AWS provider, merges inputs, pins Terraform ≥ 1.5, and points terraform_binary at scripts/terraform-shim so iebcloud’s default 0.12.31 is never used.

IAM contract (must match screenshot SIDs)

SidActionsResource
ViewSpecificResourceGroupresource-groups Get/List/Searcharn:PARTITION:resource-groups:*:ACCOUNT:*/*
TaggingReadOnlytag:GetResources, GetTagKeys, GetTagValues*

Trust: sts:AssumeRole + TagSession, principal account root, condition ArnLike aws-reserved/sso.amazonaws.com/*.

Python verify checks

  1. Role exists (iam:GetRole) — else status missing
  2. Trust JSON contains sso.amazonaws.com and sts:AssumeRole
  3. Sid ViewSpecificResourceGroup covers required Get/List actions
  4. Resource Groups ARN uses this account (or RESOURCE_GROUP_ACCOUNT_ID)
  5. Sid TaggingReadOnly on *
  6. Optional probe: tag:GetTagKeys

SSO failures are denied rows in HTML — the run still writes the report. Overall: pass / partial / fail.

Hard rules
